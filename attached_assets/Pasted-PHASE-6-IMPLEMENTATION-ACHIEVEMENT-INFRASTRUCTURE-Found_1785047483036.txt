Task: Implement the foundational infrastructure for the player achievement and progression system. No large sets of achievements, rules, automatic triggers, or display commands yet — focus purely on database schemas, repositories, service structure, and types.

Requirements:

1. Database Schemas (`lib/db/src/schema/logros.ts` or corresponding schema files, ensuring proper export registration in central database schema indexes if required):
   - `logros` table (Catalog):
     - `id`: serial primary key
     - `codigo`: text, unique, not null (e.g., "VICTORIAS_100")
     - `nombre`: text, not null
     - `descripcion`: text, not null
     - `tipo`: text, not null (e.g., "VICTORIAS", "PARTIDAS", "MVP")
     - `valor`: integer, not null (e.g., 100)
     - `activo`: boolean, not null default true
     - `createdAt`: timestamp with timezone, not null default now()
   - `logros_jugador` table (Player Unlocks):
     - `id`: serial primary key
     - `discordId`: text, not null
     - `logroId`: integer, not null references `logros(id)` on delete cascade
     - `obtenidoAt`: timestamp with timezone, not null default now()
     - `metadata`: jsonb("metadata") optional
   - Add unique constraint / index on (`discordId`, `logroId`) to prevent duplicate achievement unlocks.
   - Export corresponding Zod schemas and inferred TypeScript types.

2. Repositories:
   - Create `AchievementRepository` inside `artifacts/discord-bot/src/database/repositories/AchievementRepository.ts`:
     - Method to list active achievements.
     - Method to list achievements unlocked by a specific `discordId`.
     - Method to record a player achievement unlock safely (idempotent / ignore duplicates).

3. Service Layer:
   - Create `AchievementService` inside `artifacts/discord-bot/src/services/AchievementService.ts`:
